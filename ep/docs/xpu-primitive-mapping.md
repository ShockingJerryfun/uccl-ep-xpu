# xPU primitive mapping

Source baseline: UCCL-EP [`e51132a8`][uccl] and MXDeepEP [`5ce9cce6`][mxdeepep]. `U` denotes UCCL `ep/`; `M` denotes MXDeepEP `csrc/`. Line numbers refer to these revisions. Coverage includes the MetaX branches in `M kernels/{utils.cuh,configs.cuh,internode_ll.cu,intranode.cu,intranode_c588.cu,internode.cu,launch.cuh,exception.cuh,ibgda_device.cuh,ibgda_device_common.cuh}`, their partial-barrier callers and initialization.

This is a source mapping, not a tested port. **Candidate** means a proposed implementation with the cited language or source basis, not confirmed vendor support. No MetaX/CoreX SDK compilation or device validation has been performed. All xPU rows require target validation; V1–V10 below identify the checks. GNU `__atomic_*` builtins are compiler extensions, not standard C++ APIs; their documented memory order does not establish a GPU/CPU memory scope.

## Pending validation

- **V1 — SDK compilation and platform guards:** SDKs are unavailable. Compile every EP translation unit, ring/FIFO headers and host bindings with each vendor compiler; capture host/device predefined macros and generated device code. Check that no PTX or AMD-only builtin reaches an xPU path and no device function takes a host-only branch. `DISABLE_SM90_FEATURES` alone does not disable every `#if __CUDA_ARCH__` helper body. NVIDIA CI does not compile these branches.
- **V2 — CPU/GPU publication:** MXDeepEP's `"device"` fences and GNU atomics do not establish the required host-memory scope. Test existing `TransferCmd` publication, acknowledgement and slot reuse on mapped memory with payload checksums, sequence numbers and queue wraparound. Cover 8/32/64-bit flags, both directions and concurrent producers; validate on the final Kunpeng host as well. Inspect generated fences and atomic widths. Do not change the queue ABI or publication order.
- **V3 — Warp and launch geometry:** both vendor sources specify 64 lanes, but overload widths, subgroup masks and active-lane behavior remain untested. Verify shuffle/vote results across lanes 31/32/63, subgroup reductions and `elect_one_sync` callers. Check each launch and barrier participant count; an EP limit of 1024 threads is a software choice, not an inferred hardware maximum.
- **V4 — GPU ordering and peer memory:** an API name or a bare `atomicAdd` does not establish acquire/release or cross-device semantics. Run message-passing and contended-lock tests within a block, across blocks and across peer GPUs; check stale payloads and lost updates under each allocation type. Establish `atomicAdd_system` / `atomicSub_system` support before retaining `barrier_block`; do not substitute MXDeepEP's different byte-flag protocol.
- **V5 — Partial barriers and grid barriers:** the reference barrier assumes a particular participant layout. Stress independent barrier IDs, repeated phases and delayed warps, including send-only/receive-hook launches. Cover groups not starting at warp 0. MXDeepEP sometimes adds matching `else { __syncthreads(); }` paths; copying only its barrier call into UCCL can deadlock. Verify cooperative residency and kernel relaunch reuse separately.
- **V6 — Numeric representation:** MXDeepEP provides an E4M3/448 implementation, but the installed SDK and target card are unknown; CoreX BF16/FP8 coverage is not established. Check header signatures, conversion bytes, saturation near 240/448, zero/subnormals/NaN and BF16 round trips. Compare FP8 scales and Dispatch/Combine output with reference tensors. Compile and check `log2f` / `exp2f` error and special-value behavior.
- **V7 — Non-SM90 execution:** both ports must select existing non-TMA copies. Compile all template instantiations and confirm no TMA assertion stub is reachable. Validate cooperative launch APIs and `cg::this_grid().sync()` together; an ordinary launch cannot be assumed to support a grid barrier.
- **V8 — Clock, spin and trap:** counter units, wraparound and trap lowering are not established for the target SDK. Compare `clock64` deltas with device-event elapsed time, exercise bounded timeout tests, and inspect trap/spin code generation in an isolated test process. Retaining a cycle constant does not retain its timeout duration in seconds.
- **V9 — Host/runtime integration:** vendor PyTorch ABI, cu-bridge/CoreX extension compilation, AArch64 packages, allocation flags and IPC are untested. Build/import `uccl.ep`, then exercise allocation/free, mapped-pointer access, stream/event operations and two-process IPC. Confirm compiler/version/architecture flags from the actual SDK. The CoreX 4.4.0 guide documents `--cuda-gpu-arch`; support for nvcc-style option aliases must not be assumed.
- **V10 — Full communication:** MXDeepEP uses MXSHMEM/IBGDA and a different peer barrier; UCCL uses CPU-proxy commands. After primitive tests, run actual queue/proxy integration, two-GPU Dispatch/Combine correctness and multi-node transport integration. URMA implementation belongs to the transport owner. A single-card command/ack benchmark does not validate this path, and no AMD or xPU runtime result follows from A100 CI.
